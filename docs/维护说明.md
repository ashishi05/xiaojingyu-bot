## 100000001 广告管理

`ad_guard` 在平台消息提交到普通聊天流水线之前单独拦截目标群消息；其他群沿用原流程。初始化会移除该群的普通聊天白名单记录，`group_autojoin` 已增加排除，避免手动同步群库再次加入。2026-10-26 已通过本机管理接口启用，`status.json` 实查机器人角色为 `admin`、`can_moderate=true`；该群已从聊天白名单移除。文字广告、非商业招募和合成二维码样本的真实模型审核通过；未对真实群成员执行测试处罚。

规则：

- 最高前提：必须有消息文字或图片中的连续7位以上数字／QQ群进群链接，或模型明确确认的二维码，才允许撤回、禁言、群提示、私聊告警。三者均无则完全不动作；普通商品网址不满足条件。无图且无连续7位以上数字／进群链接时不调用模型，但报备话术仍可缓存 20 秒等待同一账号补图。图片审核失败且文字也没有连续7位以上数字／进群链接时，不发送审核失败私聊；不能把未知图片当作已确认的二维码。
- 放行社团招新、比赛招募、实验室招募、大创组队、志愿者等无商业利益的活动。普通同学二手转让、讨论兼职经历和反诈提醒不直接等同商业推广。
- 明确的兼职招募、商品推销（电话卡、床上用品等）、商家优惠，满足审核证据条件后撤回消息并禁言 `600` 秒。已有群号／进群链接／二维码证据但广告判断不足时只通知。
- 自称“活动已报备”“已向管理报备”“已报备管理勿撤”等话术并附群号或进群链接，使用高危文字规则；带二维码的同类话术由图片审核辅助确认。二维码单独出现不处罚。
- 普通商业审核要求 `decision=ad`、置信度至少 `0.98`、招揽及行动意图成立，并有至少两段可在原文核对的直接证据；二维码加报备话术也要求图片审核返回高置信广告判断。模型格式错误、超时、图片不可读或权限无法确认时不据此处罚。
- 机器人自身、两个自用账号、群主及管理员豁免。处罚前重新查询机器人和目标账号群权限。仅处理撤回和 10 分钟禁言，不自动踢人。

私聊通知优先 `10001`，失败尝试 `10002`；同一发言账号 60 秒内不重复通知，同一账号已成功禁言后 10 分钟内不延长禁言，但后续已确认的广告仍尝试撤回。通知明确各动作是否成功，审核或通知失败写日志。

数据目录：`AstrBot/data/plugin_data/ad_guard`。

- `status.json`：启动检查的群号、机器人角色、可否管理和检查时间；状态可能随群权限变更而过期，实际处罚前仍查询权限。
- `audit.jsonl`：疑似或已确认广告的原文、图片链接、判断、处理结果及通知是否发出；超过约 2 MB 时轮换到 `audit.previous.jsonl`，只保留当前与上一份。
- 当前限额：每消息最多检查前 6000 字、前 2 张带 HTTP(S) 链接的图片；无图片且无连续7位以上数字／进群链接的消息跳过模型；模型超时 25 秒，最多同时审核 2 条，待处理达到 8 条时，仅对文字已含连续7位以上数字／进群链接的情况发繁忙提醒，不额外处罚；只有未确认图片的情况保持静默。相同发送者和内容的判断缓存 10 分钟，最多 256 份；已处理消息 ID 缓存最多 2048 条。
- 使用当前默认模型进行独立审核，不附带私聊上下文、不提供工具。图片审核依赖模型实际看图能力；当前未新增本地二维码解码依赖。模型调用产生正常 API 用量。

## 界面操作反馈

`tray.ps1` 和 `maintenance/scheduled-wake/wake_settings.ps1` 通过隐藏的 `maintenance/ui-operation.ps1` 后台进程执行操作，界面计时器读取 `runtime/ui-<GUID>.json` 结果后清理。界面不再同步等待启停或任务保存；结果区分成功、等待验证和失败，失败不报告成功。启动结果核对实际 QQ 在线状态；关闭通过 `stop.ps1 -KeepTray` 处理，成功反馈后退出托盘，避免二次停止。管理页面只报告浏览器打开请求已发送，不声称页面已成功加载。唤醒设置保存后重新读取任务确认，打开窗口不改任务。

验证入口：`tests/test_tray_feedback.ps1`、`tests/test_wake_ui_feedback.ps1`、`tests/test_ui_operations.ps1`，配合现有 `test_tray_resources.ps1`。测试使用模拟进程/临时结果文件，不实际重启 QQ 或改动唤醒时间。

界面重启等待修复：Windows PowerShell 的原生命令管道及 `Start-Process -Wait` 会等待常驻后代进程，导致服务已启动但按钮迟迟不结束。托盘后台、桌面启动和定时唤醒改为 `Start-Process -PassThru` 后只对返回的脚本进程调用 `.WaitForExit()`。托盘从操作进度文件显示“关闭旧服务／启动服务并恢复登录／核对QQ在线”阶段，完成后清理结果与进度文件。真实无害进程回归见 `tests/test_service_script_wait.ps1`。
